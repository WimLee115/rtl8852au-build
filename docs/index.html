Realtek RTL8852AU · RTL8832AU · 802.11ax

The WiFi 6 driver that
actually builds on modern kernels.

An out-of-tree Linux driver for USB adapters based on the Realtek RTL8852AU / RTL8832AU (WiFi 6, AX1800) chipsets. The vendor source stopped compiling on recent kernels — this fork carries the version-gated patches that restore the build on kernel 6.1 → 7.0+, and fixes the monitor-mode crashes along the way.

What you get

Built to keep working, not just to compile today.

The scope is deliberately narrow — build reliability, stable monitor mode, and staying close to the vendor source — with the tooling to prove it.

Kernel 6.1 → 7.0+ compatibility

Twelve compile-time fixes for the API removals and signature changes that broke the vendor tree — WEXT removal, proc_ops, timer_setup, the DMA API, class_create, and the cfg80211 channel-switch / MLO radio_idx refactor. Each gate keys off LINUX_VERSION_CODE.

Verified up to Linux 7.0.12 · CI builds mainline stable + LTS

Monitor mode that stays up

The vendor RX path crashed under monitor mode in four distinct ways: a UBSAN array out-of-bounds on every WPA key op, a NULL-deref, an SKB use-after-free, and a race with a double-free. All four are fixed. A separate patch takes hw_init_mutex symmetrically so rmmod-while-associated no longer panics.

rmmod-under-load fix hardware-validated on TX20U Plus

Web dashboard

A small Flask app for the driver's runtime state and a few controls — scan, connect, MTU, txpower, module reload. Binds to 127.0.0.1 by default and gates every endpoint behind HTTP Basic Auth with a per-host token stored 0600. SSID/passphrase inputs are validated against conf-injection.

Loopback-only · per-host auth token · host-header allowlist

Test suite & CI

A Python unittest suite that exercises the module, USB binding, interface up/down, scan, cfg80211 and dmesg against the running kernel and a live adapter — writing a JSON report. Destructive reload/stability classes are opt-in and refuse to run near an active association. CI adds DKMS dry-run, shellcheck and hash-locked Python deps.

10 test classes · full DKMS install/remove verified in CI

Quickstart

Two ways to install

Plain make for a one-off build, or DKMS so the module is rebuilt automatically on every kernel upgrade. Both need the matching kernel headers.

Plain make

one-off
# dependencies
$ sudo apt install -y build-essential dkms \
       linux-headers-$(uname -r) git
$ git clone https://github.com/WimLee115/rtl8852au-build
$ cd rtl8852au-build
$ make -j"$(nproc)"
$ sudo make install
$ sudo modprobe 8852au

DKMS

survives kernel upgrades
# same deps, then:
$ git clone https://github.com/WimLee115/rtl8852au-build
$ cd rtl8852au-build
$ sudo ./dkms-install.sh

# reads dkms.conf, registers, builds,
# installs and modprobes for you.
# uninstall:
$ sudo ./dkms-remove.sh

Verify it loaded

check
$ lsmod | grep 8852au
$ ip link | grep wlan
$ dmesg | grep -iE "8852|rtw"

No wlan* after modprobe? Unplug and replug the adapter so the USB subsystem rebinds. Full walkthrough in the README.

FAQ

Common questions

Which adapters does this support? +
Any USB adapter built on the Realtek RTL8852AU or RTL8832AU chipset — WiFi 6, typically marketed as AX1800. Run lsusb and match the vendor:product ID against the supported-devices table. If your ID isn't listed but lsusb -v shows one of these chipsets, open a hardware request.
Does monitor mode work? +
Yes — that's the fork's main focus after build reliability. The vendor RX path had four separate monitor-mode crashes (a UBSAN out-of-bounds, a NULL-deref, an SKB use-after-free and a race/double-free); all four are patched. Switch with iw dev wlanX set type monitor after bringing the interface down. If NetworkManager fights you, mark the interface unmanaged.
What kernel versions are supported? +
Kernels 6.1 (LTS) through 7.0 build cleanly; every patch is gated on LINUX_VERSION_CODE, and CI compiles against distro kernels plus the newest mainline stable and longterm releases. Kernel 7.1 is not yet supported — it refactored a large set of cfg80211_ops callbacks from net_device to wireless_dev; a version-gated port is tracked as follow-up work.
Secure Boot rejects the module — now what? +
Sign the built module with your Machine Owner Key using the kernel's scripts/sign-file against MOK.priv/MOK.der, or enrol a MOK first with mokutil --import, reboot to complete the prompt, then re-sign. Step-by-step in the README troubleshooting.
Does it rebuild automatically after a kernel upgrade? +
Yes, if you install via DKMS (sudo ./dkms-install.sh). DKMS registers the source under /usr/src and rebuilds the module whenever new kernel headers land — no manual recompile after apt upgrade.
Is this affiliated with Realtek or TP-Link? +
No. It's an independent community fork of Realtek's GPL-2.0 vendor source (v1.15.0.1-2), not affiliated with, endorsed by, or sponsored by Realtek, TP-Link, ASUS, D-Link, Buffalo, Elecom or any other vendor named here. Product names and USB IDs are listed for identification only. The redistributed firmware blob is unchanged from the vendor bundle and checksum-verified in CI.
